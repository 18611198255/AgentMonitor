> 日期：2026-09-08 · 版本：v0.1（待评审）

---

## 1. 背景与目标

### 1.1 背景
V2 已实现「浏览器看板监控 Pi 会话」，但核心逻辑全部堆在单文件 `monitor_server.py` 里，`scan_sessions` 同时承载两套探测逻辑（CLI 进程扫描 / 网页版 HTTP 轮询），并靠 `USER_VISIBLE_WINDOW`、`_is_fresh`、`make_placeholder`、状态重分类等启发式补丁层层堆叠。CHANGELOG 显示近期密集修复集中在「旧任务残留 / 抖动消除 / 占位会话 / projName 显示 prompt」等**状态判定脆弱性**上，说明当前结构已经到需要重构成型的时候。

### 1.2 目标
1. **重构**：把纠缠的两套探测逻辑拆成职责单一的探测器，统一状态解析，消除靠补丁堆出来的脆弱性。
2. **新增 4 项关键能力**：成本/Token 聚合、异常告警、历史回看+搜索、会话管理（kill/重启）。

### 1.3 成功标准（可验证）
- 状态判定不再靠跨层补丁：CLI 与网页版各自一个探测器文件，`server.py` 只做合并去重与返回。
- 4 项新功能可用，各自通过下方「验收标准」。
- 全程零第三方依赖（仅 Python 标准库 + 原生 HTML/JS/CSS）。
- watchdog 守护自愈可用；看板状态在 CLI / 网页版混合场景下不抖动。

## 3. 用户与场景

- **用户**：在 iTerm2 里跑 `pi`（CLI）与浏览器 `localhost:30141`（网页版 pi-web）并行开发同一批项目的人。
- **核心场景**：
  1. 同时开多个 CLI + 网页版会话，想知道「现在谁在跑、谁在等输入、谁卡住了」。
  2. 想看今天 / 本周花了多少 token、多少钱，按项目拆。
  3. 会话卡死或服务挂了，希望主动被提醒，而不是一直盯看板。
  4. 想回看几天前某个项目的会话、按关键词搜。
  5. 卡死的会话想在看板上直接终止/重启，不用去 iTerm 找。

## 4. 功能需求

### F1 实时会话监控（对齐 V2，重构实现）
- 同时识别 CLI 会话与网页版会话，统一卡片展示。
- 状态徽章：运行中 / 等你输入 / 疑似卡住 / 空闲 / 新对话。
- 卡片字段：项目名、状态、距上次活动、最近工具、模型、token/花费、来源（CLI/网页版）、是否可跳转终端。
- 「去终端」跳转仅对 CLI 会话（有 tty）有效。

### F2 成本 / Token 聚合统计
- 展示今日 / 本周 / 累计的 token（in/out/total）与花费。
- 按项目分组聚合（TOP 项目）。
- 看板顶部统计卡 + 迷你趋势图（近 7 天）。
- **验收**：聚合数字与 jsonl 累计一致（抽样核对 ≥2 个项目）。

### F3 异常告警通知
- 规则（含阈值 + 冷却时间，避免刷屏）：
  - **卡死**：status=stuck 且持续超过阈值（默认 5 分钟）。
  - **pi-web 宕机**：30141 从「在监听」变为「不在监听」。
  - **agent 静默**：live 会话 jsonl 超过阈值（默认 15 分钟）无写入且非 waiting。
- 通知渠道：macOS 系统通知（`osascript display notification`）为主，看板红点为辅。
- **验收**：触发规则时恰好弹一次通知；冷却期内同规则不重复。

### F4 历史回看 + 搜索
- 历史视图：列出已结束会话（含时间、项目、模型、token/花费）。
- 搜索：按关键词（prompt/工具名）与项目名过滤。
- 数据走 SQLite 索引（快速），回退 jsonl（全量重建）。
- **验收**：按项目名 / 关键词能检索到目标历史会话。

### F5 会话管理操作（kill / 重启）
- CLI 会话：看板卡片提供「终止」按钮（二次确认），`SIGTERM` 优雅退出，超时 `SIGKILL`。
- 「重启」：终止后在原 cwd 重新拉起 `pi`。
- 网页版会话：无独立 `pi` 进程（引擎在 node 内），终止方式依赖 pi-web 是否提供终止 API——**待确认**；本期默认仅对 CLI 会话（有 pid）开放 kill/restart。
- **验收**：CLI 卡死会话能一键终止，`pgrep` 确认进程消失；误点有二次确认拦截。

## 5. 架构设计

```
AgentMonitor-v3/
├── agentmonitor/                # 核心包（零第三方依赖）
│   ├── __init__.py
│   ├── server.py                # HTTP 服务 + 路由（唯一入口，port 8571）
│   ├── detectors/
│   │   ├── __init__.py
│   │   ├── base.py              # Detector 接口
│   │   ├── cli.py               # CLI 探测器：pgrep -x pi + lsof（cwd/tty）
│   │   └── web.py               # 网页版探测器：/api/agent/running
│   ├── parser.py                # jsonl → Session（唯一状态解析/推断）
│   ├── index.py                 # SQLite 索引（会话元数据 + 日聚合）
│   ├── aggregator.py            # 成本/Token 聚合（按日/项目）
│   ├── alerts.py                # 异常规则 + 告警（macOS 通知 + 冷却）
│   └── actions.py               # kill / 重启会话（SIGTERM→SIGKILL）
├── dashboard.html               # 浅色仪表盘看板
├── watchdog.py                  # 守护自愈
├── start.sh / README.md / CHANGELOG.md
└── docs/                        # PRD + 开发规划
```

### 5.1 统一探测器接口（重构核心）
```python
# detectors/base.py
class Detector:
    def detect(self) -> list[SessionRef]: ...
# SessionRef = { session_id, cwd, source: 'cli'|'web', live, jumpable, pid? }
```
- `CLIDetector`：`pgrep -x pi` → `lsof` 拿 cwd/tty → 返回在终端里活跃的会话，`jumpable=True`、带 `pid`。
- `WebDetector`：`GET /api/agent/running` → `runningSessionIds` → `jumpable=False`。
- `server.py` 只做：`detect() → 合并去重 → parser 补全详情 → 返回`。
- V2 里堆在 `scan_sessions` 的启发式（`USER_VISIBLE_WINDOW` / `_is_fresh` / 占位 / 状态重分类）各自归位到对应探测器，不跨层。

### 5.2 数据流
```
jsonl（唯一事实源，只读）
   │  parser 解析
   ▼
Session 对象 ──► detectors 判定 live/jumpable ──► /api/sessions（实时）
   │
   ▼（增量写入）
SQLite 索引（sessions / daily_usage）──► /api/stats、/api/sessions?q=（历史/聚合）
```

### 5.3 模块职责边界
| 模块 | 做什么 | 依赖 | 能否独立理解/测试 |
|---|---|---|---|
| `detectors/*` | 判定「谁此刻活跃」 | 仅系统命令 / HTTP | ✅ |
| `parser.py` | jsonl → Session 字段 + 状态推断 | 无 | ✅ |
| `index.py` | SQLite 读写、增量更新、重建 | parser | ✅ |
| `aggregator.py` | 聚合查询（日/项目） | index | ✅ |
| `alerts.py` | 规则判断 + 通知 | detectors + parser | ✅ |
| `actions.py` | kill/restart | 系统命令 | ✅ |
| `server.py` | 路由编排 | 以上全部 | 薄壳 |

## 6. 数据模型

### 6.1 Session（内存对象，由 jsonl 解析）
```
session_id, file_path, cwd, project_name, model,
status(running|waiting|stuck|idle|none), activity(最近动作文本),
age_seconds, tokens_in, tokens_out, tokens_total, cost,
current_tool, live, in_terminal, jumpable, source(cli|web), pid?
```

### 6.2 SQLite 索引（派生数据，可随时重建）
```sql
CREATE TABLE sessions (
  session_id   TEXT PRIMARY KEY,
  file_path    TEXT,
  cwd          TEXT,
  project      TEXT,
  model        TEXT,
  created_at   REAL,
  last_active  REAL,
  status       TEXT,
  tokens_in    INTEGER DEFAULT 0,
  tokens_out   INTEGER DEFAULT 0,
  cost         REAL DEFAULT 0,
  source       TEXT
);
CREATE TABLE daily_usage (
  date          TEXT,
  project       TEXT,
  tokens_in     INTEGER DEFAULT 0,
  tokens_out    INTEGER DEFAULT 0,
  cost          REAL DEFAULT 0,
  session_count INTEGER DEFAULT 0,
  PRIMARY KEY (date, project)
);
```

## 7. API 设计（看板 ↔ server）

| 端点 | 方法 | 说明 |
|---|---|---|
| `GET /` | GET | 看板页面 |
| `GET /api/sessions?all=1&q=&project=` | GET | 会话列表（活跃 / 历史 + 搜索过滤） |
| `GET /api/stats` | GET | 成本/token 聚合（今日/本周/累计 + 按项目 + 近 7 天趋势） |
| `GET /api/pi-procs` | GET | 运行中 pi 进程列表 |
| `GET /api/jump?session=<id>` | GET | 跳转到对应 iTerm2 标签页（仅 CLI） |
| `POST /api/kill` | POST | 终止会话（body 带 session_id，需二次确认语义） |
| `POST /api/restart` | POST | 重启会话 |
| `GET /api/services` | GET | 服务健康（看板 / pi-web 30141 状态，供 watchdog） |
| `GET /api/alerts` | GET | 当前告警状态 / 红点 |

> 所有 API 响应 `Cache-Control: no-store`（沿用 V2 教训，避免老数据混淆）。

## 8. 非功能需求

- **零第三方依赖**：Python 仅标准库（`http.server` / `sqlite3` / `subprocess` / `urllib` / `json` / `glob`）；前端原生 HTML/JS/CSS，无框架无 CDN。
- **只读安全**：不写回、不修改 Pi 任何配置或 jsonl；`/api/jump`、`/api/kill` 均做路径/ID 白名单校验（沿用 V2 安全修复）。
- **性能**：探测器结果缓存（CLI 3s / 网页版 5s，沿用 V2），避免每次刷新重启 `lsof` 子进程。
- **健壮性**：探测器异常（`lsof` 失败 / HTTP 超时）降级返回空，不崩服务；SQLite 损坏自动重建（jsonl 可重放）。
- **兼容性**：macOS + iTerm2（跳转依赖 osascript）。
- **风格**：浅色仪表盘风——浅底 + 状态色块 + 数据卡片。
