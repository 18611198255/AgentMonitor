# Pi 会话 jsonl 真实格式（实测参考）

> 实测日期 2026-09-09，来源 `~/.pi/agent/sessions/**/*.jsonl`（489 个文件）。
> 这是 parser 的唯一依据，勿凭假设写字段名。

## 一、顶层事件类型（Top-level `type`）

| type | 出现频率 | 用途 |
|---|---|---|
| `session` | 每条会话 1 个 | 会话元数据（id、cwd） |
| `message` | 最多 | 对话消息（user / assistant / toolResult） |
| `model_change` | 中 | 模型切换记录 |
| `thinking_level_change` | 少 | 思考等级切换 |
| `custom` | 少 | pi-web 自定义事件（如 tool-selection） |

## 二、各事件结构（真实样例）

### session
```json
{"type":"session","version":3,"id":"01a08172-be76-7748-a2fa-1f78011d065d","timestamp":"2026-09-08T14:36:15.863Z","cwd":"/Users/kelvinjiang/Desktop/渔佳数据仪表板"}
```
- `id` = session_id（36 位 hex，文件名 `_` 后半段与之相同）
- `cwd` = 工作目录

### message（外层包裹内层 `message`）
```json
{"type":"message","id":"...","parentId":null,"timestamp":"...","message":{...}}
```

### message 内层对象 —— 4 种形态（按 `role` 区分）

**1. user**
```json
{"content":"<str 或 block数组>","role":"user","timestamp":"..."}
```

**2. assistant（关键，含 usage）**
```json
{"api":"...","content":[{"type":"text","text":"..."} 或 {"type":"toolCall","name":"bash","arguments":{"command":"..."}}],
 "model":"deepseek-v4-flash","provider":"deepseek","responseId":"...",
 "role":"assistant","stopReason":"...","timestamp":"...",
 "usage":{"input":1218,"output":176,"cacheRead":9984,"cacheWrite":0,"reasoning":0,
          "totalTokens":11378,
          "cost":{"input":0.00017,"output":4.9e-05,"cacheRead":2.8e-05,"cacheWrite":0,"total":0.000247}}}
```
- `content` 是 block 数组；block 两种：`{"type":"text","text":...}` 和 `{"type":"toolCall","name":...,"arguments":{...}}`
- `stopReason` 取值：`toolUse` / `error` / 其他（如 `endTurn` / 空）
- **token**：`usage.input`（入）/ `usage.output`（出）/ `usage.totalTokens`（总）
- **成本**：`usage.cost` 是对象，取 `.total`

**3. toolResult**
```json
{"content":"...","isError":false,"role":"toolResult","timestamp":"...","toolCallId":"...","toolName":"bash"}
```
- 有时带 `details` 字段（可为空数组）

**4. assistant（error 形态）**
```json
{"api":"...","content":"...","errorMessage":"...","model":"doubao-seed-2-0-lite-260215","provider":"...","role":"assistant","stopReason":"error","timestamp":"...","usage":{...全0...}}
```

### model_change
```json
{"type":"model_change","id":"...","parentId":null,"timestamp":"...","provider":"deepseek","modelId":"deepseek-v4-flash"}
```

## 三、parser 字段映射（结论）

| 目标字段 | 来源 |
|---|---|
| session_id | `session.id` |
| cwd | `session.cwd` |
| model | `assistant.message.model`（兜底 `model_change.modelId`） |
| tokens_in | Σ `assistant.message.usage.input` |
| tokens_out | Σ `assistant.message.usage.output` |
| tokens_total | Σ `assistant.message.usage.totalTokens` |
| cost | Σ `assistant.message.usage.cost.total` |
| 最近工具 | 最后一条 assistant 的 `content` 里 `toolCall.name` |
| 状态 | 见下方状态机 |

## 四、状态机（沿用 V2 逻辑，移植自 `monitor_server.py:parse_session_jsonl`）

- assistant 消息：
  - content 含 `toolCall` → `running`（记 tool，记 tool 的 path 参数到 tool_paths）
  - `stopReason == "error"` → `stuck`
  - `stopReason == "toolUse"` → `running`
  - 其他（纯文本）→ 若自上次 user 输入以来跑过工具则 `running`，否则 `waiting`
- toolResult 消息：`isError` → `stuck`，否则 `running`
- user 消息：记录 first_user / last_user 文本
- 时间兜底：距最后消息 `since` 秒
  - `since > IDLE_THRESHOLD`：`> 3*STUCK_THRESHOLD` → `idle`，否则 `stuck`
  - 否则若 `running/waiting` 且 `since > STUCK_THRESHOLD` → `stuck`

## 五、与计划 Task 2 示例的差异（重要）

计划示例测试代码里写的是 `{"type":"assistant","message":{"usage":{"input_tokens":...}}}` —— **错误**。
正确写法：
```python
{"type":"message","message":{"role":"assistant","model":"deepseek-v4-flash",
  "usage":{"input":10,"output":5,"totalTokens":15,"cost":{"total":0.0001}},
  "content":[{"type":"text","text":"hi"}],"stopReason":"endTurn"}}
```
- 字段是 `usage.input` / `usage.output` / `usage.totalTokens`，**不是** `input_tokens` / `output_tokens`
- `cost` 是对象，取 `.total`
